# DOS na 1581, BIOS a emulátor v cartridge

`build/1581/FD64.CRT` obsahuje C64 emulátor a 8KiB GLaBIOS sestavený
s konfigurací ARCH_EMU/CPU_8088 a volbami z `tools/build_glabios.py`.
`build/1581/FD64.D81` obsahuje 720KiB FAT12 jednotku FreeDOSu. Po startu
se disk nekopíruje do REU: BIOSové sektorové služby čtou a zapisují přímo
přes IEC do mechaniky 1581 na zařízení 8. Operační paměti PC stačí 1MiB REU.
Původní varianta s disketou ve druhém MiB REU je zachovaná samostatně.

    python -B tools/dev.py build
    python -B tools/dev.py prepare-1581
    python -B tools/dev.py run-1581

Příprava cartridge se může opakovat. Existující FD64.D81 se zachovává včetně
uživatelských zápisů. `run-1581` otevře viditelný PAL VICE s úplnou emulací
procesoru mechaniky 1581, cartridge a 1MiB REU; monitor je na portu 6513.
Studený start vykoná skutečný GLaBIOS POST. F1/F3/F5 volí pohled obrazovky.

Cartridge používá Magic Desk CRT, typ 19: ROM okno 8000–9FFF a bankování
v DE00 (IO1). Tato konfigurace nepřekrývá DF00 s registry REU. EasyFlash
má v IO2 vlastní RAM, proto pro tuto kombinaci nepoužíváme jeho mapování.
Emulátor se při resetu zkopíruje z bank 1–7 do C64 RAM a cartridge se vypne.
Po vymazání PC RAM krátká rutina v 033C načte BIOS z banky 8 do FE000
v REU. Obnoví mapování 01, softwarový stack cc65 i stav IRQ; CPU začíná
na FFFF:0000. BIOS se nečte z diskety a x86 nadále vykonává 6510.

## Rozložení diskety

D81 má 80 stop po 40 logických 256B blocích. PC vidí 1440 sektorů po
512 bytech, geometrii 80 cylindrů / 2 hlavy / 9 sektorů a bootovací A:.
Každý sektor PC používá dva sousední bloky 1581. Není to běžná PC disketa
vložená do 1581: data jsou uložena v jejím nativním formátu.

| Stopy 1581 | Obsah |
|---|---|
| 1–39, 41–73 | Raw 720KiB FAT12 FreeDOSu; sektory označené obsazené v CBM BAM |
| 40 | Hlavička, BAM a adresář CBM |
| 74–80 | Volná oblast CBM; BIOS ani emulátor tu nejsou |

Mapování používá `track = LBA / 20 + 1`, s přeskočením stopy 40;
`sector = (LBA % 20) * 2 + half`. Backend používá U1/U2 a buffer-pointer
B-P, kontroluje chybový kanál mechaniky a odmítá LBA mimo 0–1439.
Zápisy nemění BAM, CBM adresář ani ostatní sektory. Standardní pomalé IEC
je implementované; vlastní fastloader ani burst protokol zatím ne.

Na tomto hybridním médiu se nesmí použít CBM VALIDATE: raw PC oblast
nemá CBM řetězce souborů a rekonstrukce BAM by ji prohlásila za volnou.
Pro soubory DOSu se používají příkazy DOSu. Klávesnice varianty 1581
umí také tečku, zpětné lomítko, dvojtečku a přesměrování `>`; Shift
odesílá jako skutečné make/key/break scancodes přes IRQ1.

## Ověření

    python -B tools/dev.py test
    python -B tools/dev.py test-1581-sectors
    python -B tools/dev.py test-1581

Sektorový test v úplné emulaci procesoru 1581 čte boot sektor, zapisuje
sektory 779/780 (přes přeskočenou stopu 40) a 1439, zavírá a znovu otevírá
kanály a kontroluje každý byte. Po vypnutí VICE se porovnává skutečný D81
na hostiteli: přetrvávají jen požadované změny. Report je
`build/1581-check-report.json`. Každý pokus používá vlastní testovací médium.

Úplný test začíná resetem cartridge, vykoná POST, FreeDOS/FreeCom a příkazy
VER/DIR/ECHO. Testovací AUTOEXEC navíc vytvoří a přečte WRITE81.TXT.
Po ukončení testovací instance se z D81 vyjme FAT12 a ověří přesný obsah
souboru vytvořeného DOSem. Samotný nativní boot ani dřívější sektorový test
nejsou důkaz dokončení tohoto cartridge/DOS běhu. Jeho report je
`build/glabios-1581-test-report.json`; úspěch vyžaduje status passed.

Běh 2026-10-11 prošel: `status: passed`, POST i guest marker true,
2 180 551 x86 instrukcí, 387 přečtených a 5 zapsaných sektorů, disková
chyba 0. Po vypnutí VICE byl ve skutečném D81 nalezen WRITE81.TXT
s přesným obsahem `FD64 1581 WRITE OK\r\n`. Studený test včetně příkazů,
zápisu a kontroly trval na místním PC ve warp režimu 766,0 s. Není to
přímé srovnání s dřívějším bootem z REU: zahrnuje mechaniku i další DOSové
operace. Report uchovává hashe CRT, PRG, symbolů i počáteční/konečné D81.

Po úspěšném testu lze skutečný nabootovaný stroj obnovit:

    python -B tools/vice_resume.py --name glabios-1581
    python -B tools/verify_snapshot.py --name glabios-1581

Snapshot se obnovuje s jeho vlastní testovací D81 a CRT uvedenými v reportu.
Ověření píše nový ECHO a hledá samostatnou odpověď ve skutečném obrazu
VIC-II. Ruční použití běžné diskety slouží přes `run-1581`.
Také obnovení tohoto stroje prošlo: `build/1581-resume-report.json` má
status passed a nová odpověď `FD64 1581 OK` byla ověřena v pixelech VIC-II.
Následně prošel i ruční `TYPE WRITE81.TXT`: backend provedl další tři
sektorová čtení a text souboru se znovu objevil na řádku 23 skutečné
obrazovky. Report je `build/1581-file-read-report.json`. Otestovaný DOS
zůstává otevřený ve viditelném VICE.

Fyzická cartridge, expander, REU a mechanika nebyly tímto testem ověřené.
Výsledky platí pro VICE; firmware konkrétního KFF je samostatná validace.
